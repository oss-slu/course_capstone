## Description

**Developers** practice substantive code review so that feedback becomes a learning habit, not a checkbox.

**Instructor** spot-checks PR comments and monitors Slack so that shallow reviews are identified and coaching opportunities arise.

## Acceptance Criteria

- [ ] GitHub PR comments spot-checked
- [ ] Slack monitored for review discussions/questions
- [ ] Teams with minimal review activity noted
- [ ] Sprint 1 close activity observed

## Stretch AC (Review Quality)

- [ ] All Developers have reviewed at least one PR
- [ ] Reviews address substance (architecture, testing, clarity) not just style
- [ ] Teams discussing code in Slack, not just GitHub

## Notes

Week: 3 (Sprint 1 Close)

**Discussion Focus:** What makes a good code review, giving constructive feedback, learning from others' code.

**Observable in:** GitHub PR comments, Slack team channels.

**Activity tie-in:** Good Practice - Peer Code Review, Sprint 1 Close.
